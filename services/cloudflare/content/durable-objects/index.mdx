## A small stateful service for each thing in your app

Think **one named instance of your code, with its own database**. Give a chat
room, multiplayer session, shared document, or tenant workspace its own object.
Requests for the same name reach the same object, bringing the code that manages
that thing together with its stored state.

For a chat room, the object can coordinate the connected participants and keep
room history. For a shared document, it can coordinate edits. The useful part
is being able to address that stateful unit directly, instead of spreading its
coordination across otherwise separate request handlers.

The diagram uses a chat room as a concrete example. Other rooms get their own
objects. Memory is temporary; data that must survive instance lifecycle changes
belongs in the object’s durable storage.
[Cloudflare’s design guidance](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/)
explains how to choose that unit of state.

## Object identity survives; the active instance can change

A room’s durable storage and its current in-memory state have different
lifetimes. Eviction discards memory; a later activation reconstructs an instance
that can read its stored data. Put room history in storage and treat active
connections or temporary calculations as lifecycle-dependent.
[Object lifecycle](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/).

Use the [Workers page](/cloudflare/workers/#runtime-concurrency) for the base
single-threaded execution model, but do not transfer stateless Worker routing
assumptions to a named Durable Object. Identity is the reason callers can meet
at the same stateful unit.

<section slot="deployment">

## Deployment

Export the Durable Object class, configure its namespace binding and class
lifecycle declaration, then deploy the owning Worker with Wrangler. Follow the
current configuration guide when adding or changing classes; these changes
are distinct from editing the data inside existing objects.
[Durable Object setup](https://developers.cloudflare.com/durable-objects/get-started/),
[Class lifecycle configuration](https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/).

`npx wrangler dev` wraps local execution. Initialize test state by calling object
methods rather than expecting a generic database-seeding command.
[Local object data](https://developers.cloudflare.com/workers/local-development/local-data/).
