## Object bytes live outside the Worker

An R2 binding gives your code access to a bucket. It does not load the bucket
into the isolate. The architecture separates API access, metadata, read caching,
and stored object bytes. Your Worker is one caller; an S3 client uses a different
API surface. [R2 architecture](https://developers.cloudflare.com/r2/how-r2-works/).

Choose local tests for the interface you actually use. A passing Workers-binding
test says nothing about an S3 client’s request signing or operation support.
[R2 S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/).

<h2 id="api-example">API example</h2>

Bind a bucket as `FILES` and upload an object named `hello.txt`. This handler
streams that object to the client, preserving its HTTP metadata. Put it in
`src/index.js`; call it with GET.

**wrangler.jsonc — relevant configuration**

Merge this into your existing Worker configuration.
Replace the bucket name with yours; `FILES` becomes `env.FILES`.
[Configuration reference](https://developers.cloudflare.com/workers/wrangler/configuration/#r2-buckets).

```json
{
  "r2_buckets": [
    {
      "binding": "FILES",
      "bucket_name": "<YOUR_BUCKET_NAME>"
    }
  ]
}
```

**src/index.js**

```javascript
export default {
  async fetch(request, env) {
    if (request.method !== 'GET') {
      return new Response('Use GET', {
        status: 405,
        headers: { Allow: 'GET' },
      });
    }
    const object = await env.FILES.get('hello.txt');
    if (object === null) {
      return new Response('Object not found', { status: 404 });
    }
    const headers = new Headers();
    object.writeHttpMetadata(headers);
    headers.set('ETag', object.httpEtag);
    return new Response(object.body, { headers });
  },
};
```

To store text from Worker code, use
`await env.FILES.put("hello.txt", "Hello from R2!")`.
This uses the Worker binding rather than S3 credentials. The example serves one
fixed object; it does not implement range or conditional GET handling.

[R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

<h2 id="latency">Latency</h2>

**Published upload example: roughly 500 ms p50, down from roughly 2 seconds.**
Cloudflare’s February 3, 2026 Local Uploads announcement reports this improvement
in upload time to last byte (TTLB), with up to a 75% reduction in its tests.
This is a vendor benchmark for that feature, not a general R2 `put()` latency
or a guarantee. The short announcement does not specify enough workload details,
such as object size, to apply those absolute times to every upload.
[Local Uploads benchmark](https://developers.cloudflare.com/changelog/post/2026-02-03-r2-local-uploads/).

**Reads depend on the path.** Bucket location, caller location, and access
patterns matter. A custom-domain CDN cache hit can bypass the R2 gateway; an
uncached request must retrieve the object through R2. The architecture guide
does not give a general millisecond range for GET, HEAD, or PUT. CDN-cached
copies may remain stale even though R2 itself is strongly consistent.
[R2 architecture and performance](https://developers.cloudflare.com/r2/how-r2-works/).

Our measurement guidance: separate metadata/first-byte latency from full object
transfer time, and compare cached public downloads with direct binding or S3
requests. Record object sizes and caller/bucket regions with p50, p95, and p99.

<section slot="deployment">

## Deployment

Create the hosted bucket and configure the application’s access. Workers use
a bucket binding; external S3 clients use R2’s S3 endpoint and credentials.
Deploying application code is separate from uploading object data.
[R2 setup](https://developers.cloudflare.com/r2/get-started/).

Wrangler provides the local wrapper (`npx wrangler dev`) and object-management
commands. Use `--local` when seeding local objects. Use a staging bucket for
hosted binding or S3 integration tests.
[Local objects](https://developers.cloudflare.com/workers/local-development/local-data/).
